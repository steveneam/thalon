# ADR 0005 — Pass-3 re-charter: Thalon-first dogfood, frontend-first order, intel v2 (A12 / Sprint 6)

- **Status:** accepted (founder direction at the pass-3 checkpoint, 2026-07-06 planning session; elaboration delegated to lead and ratified same day)
- **Context home:** `CHARTER.md` (Sprint-6 bucket table + amendment A12); design home `docs/FRONTEND.md`
- **Supersedes:** the pass-3 paragraph under Sprint 5 (scope unchanged in substance, now bucketed); the "pillar-#1 tenant = the founder's first company" sequencing from A6/A7 planning (deferred, not cancelled)

## Context

Sprint 5 closed complete (B5.1–B5.4; suite 580/3; Hyperframes render live-ready). Pass 3 — live verification + real drivers — was chartered as a founder-shaped checkpoint. At the 2026-07-06 planning session the founder set the shape and added product direction in four areas: (1) a recommended-search/ranking frameworks summary (Facebook EdgeRank → modern two-stage recommender architecture) supplied as design input for the intel feature; (2) intel must let the operator select/describe the topic **areas** to monitor — which is exactly the un-built "niches" third of the chartered B3.12 watchlist (accounts/queries/niches); (3) the landing page + workspace frontend build starts now, founder references supplied; (4) **Thalon dogfoods itself** — the engine's own marketing is the first real tenant workload, which the charter anticipated (ratified decision 3: tenant #0 = "Thalon-markets-Thalon").

Research findings that shaped the intel design (verified against official docs, 2026-07-06):

- **YouTube Data API (June-2026 quota change):** `search.list` now draws from its own bucket, default ≈**100 calls/day** — discovery searches are scarce and must be rationed per area; the new `videos.batchGetStats` (1 unit, own bucket) makes engagement-snapshot refreshes across tracked items cheap. Channel-upload polling stays cheap.
- **Bluesky/AT Protocol:** public AppView, keyless `searchPosts`, generous limits — the abundant discovery source. Per-driver quota budgets are therefore config, not code.
- **Third-party transcript sites are retrieval, not ASR:** they fetch YouTube's precomputed caption tracks via unofficial endpoints; YouTube actively blocks datacenter IPs, forcing a rotating-residential-proxy arms race. This re-validates the A8 design — the hosted-vendor adapter absorbs that risk behind the `TranscriptProvider` seam; the engine never fetches platform caption endpoints itself.

## Decision

1. **Thalon-first dogfood.** Tenant #0 gets the real, deep profile (tracked in-repo — it is the self tenant and carries no guarded tokens): pillar video #1 is about Thalon; the landing page is Thalon's own web presence; the self tenant's monitored areas are its real niches. The founder's first company onboards **later** as a pure runtime-config tenant — a stronger multi-tenancy proof (the B2.1 pattern) and its guarded-token handling stays out of the hot path.
2. **Frontend first, hand-built shell, dogfooded content.** The landing page (founder-specified 4 sections) and workspace shell are hand-built — product UI is the product, not tenant content. The landing page's copy/claims become B3.15 grounding sources, and its feature-demo clips are **real Hyperframes renders** — future site iterations are generated + judged through Thalon's own queue ("hand shell, dogfood content"). Full spec: `docs/FRONTEND.md`, including the 10-second-rule design invariant and the conversion/stickiness mechanics the founder delegated.
3. **Intel v2 = monitored areas + deterministic ranking.** Per-tenant **areas** (name + free-text description, runtime config) fill the watchlist "niches" slot and drive both stages of a two-stage pipeline, adopting the supplied frameworks doc honestly: **candidate generation** (areas expand deterministically to per-platform queries; accounts polling as today) then **ranking** — an EdgeRank-shaped deterministic score: *relevance-to-area* (embedding cosine against the area description — pgvector already in place) × *engagement ratios* (existing share/bookmark math) × *velocity/freshness* (existing single-sweep + longitudinal Δ-velocity), all weights per-tenant config, reason strings preserved. Deliberately **not** adopted: neural two-tower models, federated learning, GenAI-synthesized feed items — wrong scale; deterministic math + embeddings is the honest fit (SPINE §1). Operator promote/dismiss actions on intel cards feed `edit_diffs` → eval rows (the feedback loop at batch scale).
4. **Transcript live drivers are elevated** (founder direction: a learning/dogfood input channel — paste a video URL, get a timed source to ground generations). Both B4.8 drivers go live in-pass: local Whisper for owned/permitted media; the hosted vendor adapter for third-party videos (keyed runtime config — vendor candidates verified to match the seam's POST+token shape; a thin per-vendor response-mapping is the swap lever).
5. **Sequencing** (founder answers, 2026-07-06): frontend first → self-tenant profile + demo content → intel v2 → live drivers → origination live loop (pillar #1 end-to-end, closing B3.11's waterfall + the Sprint-5 carried follow-ups) → deploy + exit gate. Bucketed as B6.1–B6.7 in the charter. B3.11's parts distribute: profile editor/switcher UI → B6.2/B6.3; B2.5 pinned-drive opener + B2.3 waterfall on the generated pillar → B6.6.
6. **Still out of scope:** no publish path (B3.1 stays pulled; OAuth apps remain a parallel [you] paperwork track); B3.14 model choice and intel-digest push are recorded as parked in `docs/FRONTEND.md`.

## Consequences

- The first real dogfood needs **no gitignored tenant config** — the self tenant is tracked, so every agent session can exercise it without vault access; the guard boundary stays cold.
- The landing page becomes a standing dogfood artifact: its demo clips exercise the render driver, its copy grounds B3.15, and its waitlist is the first real user-facing write path (one additive `waitlist` table; bounded schema window in B6.1, monitored-areas config in B6.4 — each re-freezes at merge).
- Intel's poller design is quota-shaped from day one: per-driver budgets as config (YouTube search rationed ≈100/day, batch stat refresh cheap; Bluesky abundant), so live polling can't silently exhaust a free tier.
- [you] items consolidated: domain registration + pricing-tier content (non-blocking, B6.1/B6.7) · gateway credit top-up (B6.5+) · transcript-vendor key (B6.5) · LinkedIn/X OAuth apps (unchanged long pole, not in Sprint 6).
