# ADR 0004 — Render driver default: Hyperframes; Remotion demoted to recorded swap path (A11 / B5.1)

- **Status:** accepted (founder ratification of the A11 charter, 2026-07-05; implemented by the B5.1 render lane)
- **Context home:** `CHARTER.md` (Sprint-5 bucket table + amendment A11); kickoff reading `docs/research/hyperframes-integration.md`
- **Supersedes:** the Remotion licence stance in ADR 0003 §3 (growth gate) — **the gate is retired**, not because it fired but because the default driver no longer carries it.

## Context

B3.10 shipped the render seam thin (pass 1, A9): a `RenderTarget` interface, a deterministic fake, SRT + manifest artifacts under a content-addressed cache — with Remotion pencilled in as the eventual real driver behind a **growth-gated commercial licence** (free ≤3-person companies incl. for-profit; ADR 0003 §3). At the Sprint-4 exit checkpoint the founder ratified A11: the video family gets a deterministic-first creation model, and **Hyperframes** — HeyGen's Apache-2.0 HTML→video framework (headless chromium + ffmpeg, both already in the B4.7 toolchain) — becomes the **default** render driver. The framework was verified real before chartering (33k stars, active releases) and its docs were read around into the pinned research doc every Sprint-5 lane starts from.

Why it fits this engine specifically: compositions are plain HTML+CSS+GSAP ("agents think in HTML" — our template generator emits it deterministically from schema'd data); its lint package is browser-free static analysis, so validation can run in **core** before any chromium spend (SPINE §1); its determinism contract ("same composition always produces the same video") matches our content-addressed cache; and its keyless local audio stack (Kokoro TTS · Whisper alignment · MusicGen) upgrades the pass-3 story with zero new vendors (A5 pattern: hosted APIs stay optional keyed adapters).

Comparison (from the research doc, condensed):

| | Hyperframes | Remotion |
|---|---|---|
| Authoring | HTML+CSS+GSAP (template-generatable from data) | React/TSX (code + build step) |
| GSAP fidelity | frame-accurate (paused timelines, seek per frame) | real-time ticker drifts during render |
| Editing surface | DOM rendered == DOM edited (SDK emits RFC-6902 patches) | code + rebuild |
| Licence | **Apache 2.0, free at any scale, no per-render fees** | custom commercial; company-size thresholds |
| Capture | BeginFrame (deterministic; Linux/Docker) / screenshot fallback | screenshot-based |
| Where Remotion still wins | — | mature massive-scale Lambda; React design-system shops |

## Decision

1. **Hyperframes is the default render driver**, implemented as `createHyperframesRenderTarget` behind the unchanged B3.10 `RenderTarget` seam: render manifest → deterministic HTML composition (`composition.ts`; template + data, brand styling from the active profile as data) → two-belt lint gate → `@hyperframes/producer` `createRenderJob`/`executeRenderJob` → MP4 into the existing `renders/pillar/<sha256(manifest)>/` cache (key scheme untouched, test-pinned; `video.mp4` is an additive artifact). Root width/height/duration are compile-time literals in the markup and fps is baked into the render job — none is script- or variable-settable, per the composition contract's forbidden-pattern list.
2. **Driver selection is config:** `RENDER_DRIVER` env (platform env choke point) → `getRenderTarget()`; default `hyperframes`, `fake` for tests/dev. **`remotion` is a named registry entry that fails loud** — the recorded swap path: same seam, no implementation, selecting it explains exactly that. The `remotion`/`@remotion/cli` devDependencies from B4.7 remain installed as swap-path readiness; **the A6/ADR-0003 growth gate is retired** — it re-arms only if the swap is ever taken.
3. **Version pin, exact (pre-1.0):** `@hyperframes/producer@0.7.33`, `@hyperframes/lint@0.7.33` (engine dependencies) and the `hyperframes@0.7.33` CLI (engine devDependency, resolved by the doctor probe via `npx --no-install`). No caret ranges. Bump policy: all three move **lockstep, only at bucket checkpoints** (the research doc's drift warning: local↔deployed producer version skew surfaces as Lambda "plan hash mismatch"). API deviations found against the research doc's paraphrase were verified from the shipped 0.7.33 types and coded to: `executeRenderJob(job, projectDir, outputPath, onProgress?, abortSignal?)` returns **void** (outputs land at `outputPath` and on the mutated job), and timeouts are an `AbortSignal` concern (`RenderCancelledError.reason: user_cancelled | timeout | aborted`, mapped onto the loud-failure taxonomy as `HyperframesRenderError`).
4. **Validation gates before render spend (SPINE §1), two belts.** Belt 1: `assertCompositionSafe` — the research doc's forbidden-pattern list as an always-on, dependency-free scan of the parts the generator owns (inline script bodies, markup attributes, root compile-time attrs), deliberately blind to judged text content so a narration mentioning `Math.random` can't false-positive. Belt 2: `@hyperframes/lint`'s `lintHyperframeHtml` (pure static analysis, injectable seam) — error findings throw before any chromium process spawns. `lintMediaUrls` is deliberately NOT run: it issues network HEAD checks, and the template embeds no remote media by construction, so the gate stays offline.
5. **Telemetry/feedback: opted out.** The CLI collects anonymous usage telemetry, on by default (checked at install time as the research doc required). Mechanisms verified at 0.7.33: `hyperframes telemetry disable` (persists in `~/.hyperframes/config.json`) and the `HYPERFRAMES_NO_TELEMETRY=1` env var. Decision: **opt out everywhere** — executed on the dev machine 2026-07-05; the `npm run doctor` probe sets `HYPERFRAMES_NO_TELEMETRY=1` on its spawn; CI/production environments must set the same var (it is config, recorded here). The in-process producer path our renders use showed no telemetry surface beyond the CLI counter; the opt-out covers both regardless. The `hyperframes feedback` command is operator-initiated only — never invoked by the engine.
6. **GSAP runtime (licence note).** Compositions load GSAP exactly as the official scaffold pins it — `cdn.jsdelivr.net/npm/gsap@3.14.2` in `<head>` (a preload before the frame clock, not a render-time fetch; the constant is `COMPOSITION_GSAP_SRC` and belt 1 rejects any other external script). GSAP ships under Webflow's "Standard 'no charge'" licence — free including commercial use, **no gate**, and no GSAP code is embedded in this repo. Swap path if fully-offline renders are ever required: vendor the pinned file into the composition dir behind the same constant.
7. **Windows capture fallback: accepted.** BeginFrame determinism is Linux/chrome-headless-shell; Windows dev renders fall back to screenshot capture — correct output, not byte-identical across machines. Harmless by design: the render cache keys on the **manifest hash, never output bytes**. Cross-machine byte-identity (Docker mode / Lambda) is a production-artifact concern for pass 3+.

## Consequences

- The default video path carries **zero licence gates**: Apache 2.0 end to end (producer + lint LICENSE files verified in the shipped packages), free at any scale — the launch-gate ledger loses its only render entry.
- The seam proved itself: the B3.10 interface, cache, and key pins absorbed a complete driver swap with no contract change — `renderPillar` and every existing pin test are byte-untouched.
- Verified on 2026-07-05 (this machine, $0): the generated composition passes the real `@hyperframes/lint` (0 errors), and the real producer rendered it end-to-end — 258 frames @ 30fps, 1080p, streamed capture + ffmpeg assemble → playable MP4 — via the screenshot fallback. The executable form of that smoke is `hyperframes-smoke.test.ts`, gated behind `RUN_RENDER_SMOKE=1` and never set in CI.
- The direction-export mapping (`compositionSpecFromDirectionExport`) is already wired for B5.2's staged videos — aspect/fps/pacing arrive compile-time from the direction doc; the B5.4 UI gets its per-stage low-res previews from `@hyperframes/player` with **no render at all** (research doc §B5.4).
- Pre-1.0 risk is contained but real: minor versions may move the API. The pins are exact, the doctor seam reports the installed reality, and any bump is a checkpoint decision with the research doc re-verified against the new types.
