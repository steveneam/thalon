# ADR 0002 — Sprint-2 expansion: timed sources, waterfall clip plans, exemplar library, demo plans (A5)

- **Status:** accepted (founder, 2026-07-04)
- **Context home:** `CHARTER.md` (revised Sprint-2 bucket table + amendment A5); planned lanes in `COORDINATION.md`

## Context

At the Sprint-1 exit checkpoint the founder supplied three references for integration: a content-waterfall repurposing method (one pillar piece → platform-native derivatives), a viral-content training-pipeline blueprint (trend mining, exemplar datasets, critic models, human-in-the-loop correction loops), and an Apache-2.0 visual-RAG project (documents rendered to screenshot tiles, retrieved by visual similarity). Review against the build state found the waterfall concept and the correction loop **already implemented** by the Sprint-1 slice (fan-out; same-transaction `edit_diffs` → `eval_cases`). The genuinely new capabilities are: time-coded sources (video transcripts), clip-plan generation from long-form pillars, an exemplar library retrieved into fan-out context, and a judged demo-plan slice (site crawl → storyboard → deterministic browser capture) fronting the Sprint-3 demo-video pipeline.

## Decision

1. **B2.2 — timed ingest, and the sprint's single contract window.** All Sprint-2 schema lands in one reviewed change: `source_chunks.start_ms/end_ms` (nullable); `sources.kind` += `video_transcript | exemplar | voice_sample | site_crawl`; `sources.modality` + `visual_ref` (the visual-tier seam); generic per-source engagement metrics (`metric_name`/`metric_value` — never hard-coded platform metrics); `drafts.format` += `clip_plan | demo_plan`; the pending unique index on `sources (tenant_id, content_hash)`. The contract re-freezes at B2.2 merge.
2. **Transcript capability is built in-house.** The caption parser (SRT/VTT/plain), time-coded chunking, and all downstream segmentation are repo code — deterministic core. Fetching transcripts for videos we don't own goes behind one `TranscriptProvider` seam: **self-hosted Whisper (MIT) is the strategic driver**; hosted transcript APIs are optional convenience adapters (any commercial gate = config with a swap path, per licensing hygiene). Operator-supplied caption files are the zero-dependency default — for the primary waterfall case the pillar video is the tenant's own.
3. **B2.3 — waterfall clip plans, core-first.** Deterministic candidate windows (chapter markers, pause gaps, duration bounds) computed in core; highlight-select (shell — already in the SPINE §1 shell inventory) ranks and refines; output is a `clip_plan` draft (start/end + hook + captions + platform copy) judged by G3 against the transcript and approved in the same queue as every other draft. No rendering — that stays B3.3/B3.4.
4. **B2.4 — exemplar library as retrieval, not fine-tuning.** High-performing reference posts and the tenant's own voice samples enter as sources, embed into the existing grounding index, and are retrieved top-k into fan-out context; every run records the exemplar ids it used (provenance). Invariants: **exemplars are grounding-only, never republished** — a deterministic n-gram overlap gate blocks verbatim reuse (new open-ended `judge_results.gate` value; zero migrations); PII is stripped at ingest.
5. **B2.5 — demo-plan slice (front half of the Sprint-3 demo-video pipeline).** Site crawl (robots.txt + rate limits enforced in core, never delegated to a model) → flow map → storyboard draft judged against the crawl (referenced elements/claims must exist) → operator-approved plan → deterministic Playwright drive → raw capture: video + synthetic-cursor overlay + timestamped event trace with element bounds, content-addressed. A failed step fails loudly at capture time, before any render spend. No composition/render.
6. **B2.6 — queue UI for the new formats**, built against contract mocks; also closes the queued Sprint-1 UI follow-ups (approve-panel refresh after save-edit, aborted-run rows in the feed, operator re-judge action).
7. **Visual-ingest tier: seam now, service later.** The `modality`/`visual_ref` columns land in B2.2; the visual-RAG sidecar becomes pulled bucket **B3.7** (Apache-2.0; a Python service behind the ingest seam, never a dependency of the TS monolith; compute-infra-shaped — pulled once B2.4 proves exemplar value in dogfood).
8. **Parked / rejected.** Trend-radar/outlier mining folds into B3.5 analytics when chartered (official platform APIs only). Model fine-tuning is parked indefinitely — the eval corpus the queue accumulates *is* the fine-tuning dataset if that bucket is ever pulled, so waiting costs nothing. Rejected outright: terms-of-service-evading scraper architectures (headless clusters on rotating residential proxies, DOM-evasion) — official APIs and operator-supplied data only.

## Consequences

- Sprint 2 grows from one bucket to six, but B2.3–B2.6 are the Sprint-1 machinery with new source kinds and draft formats — no new architecture, and the contract opens exactly once, which keeps the parallel-lane partition clean (planned lanes: `COORDINATION.md`).
- New executable ratchets land with their buckets: exemplar overlap gate (invariant), crawler robots.txt/rate-limit enforcement in core (invariant), PII strip before exemplar/eval storage (invariant).
- Playwright (Apache-2.0) enters as the drive/capture dependency at B2.5. The Remotion licence question stays untouched until B3.3/B3.4 is chartered (recorded launch gate with a swap path).
- The B2.5 event trace is designed as the direct input to B3.4 composition (auto-zoom from recorded element bounds), so no capture work is discarded when rendering is chartered.
- The waterfall closes a compounding loop: a finished demo video is itself a pillar source whose narration transcript is born with timestamps — B2.3 cuts shorts from it with no transcription step at all.
